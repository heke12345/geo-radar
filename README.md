# GEO Radar · 生成式引擎优化诊断工具

面向 GEO（Generative Engine Optimization，生成式引擎优化）服务场景的一站式诊断工具。输入品牌名 → 自动生成常见问题 → 在多个大模型里测试 → 给出引用率/排名/情感 → 定位「品牌被 AI 引用」这条逻辑链断在哪一环 → 输出可执行的提升方案。

**线上地址**：https://heke12345.github.io/geo-radar/

---

## 快速开始（本地运行）

纯静态项目，无需构建、无依赖安装。任选一种方式起本地服务器：

```bash
# 方式一：Node（推荐，项目已用它测试）
npx serve .          # 或任意静态服务器

# 方式二：Python
python3 -m http.server 8000
```

然后浏览器打开 `http://127.0.0.1:8000/` 即可。

> 直接双击 `index.html` 也能开，但部分浏览器对 `file://` 下的 fetch 有限制，建议走本地服务器。

## 功能模块（对应侧边栏）

| 视图 | 说明 | 关键函数（app.js） |
|---|---|---|
| **品牌输入** | 输入品牌名，启动诊断 | `startAnalysis()` |
| **问题生成** | 自动生成该品牌的常见提问 | `genQuestions()` |
| **多模型测试** | 在多个大模型里跑测试（真实/模拟） | `runTests()` / `realTest()` |
| **排名与引用** | 各平台引用率、排名、情感 + 数据源归因 + 实测 TOP 引用源 | `buildRank()` / `buildAttrGrid()` / `buildSrcRank()` |

### 两种运行模式

- **演示模式（默认）**：全部走模拟数据，任何人打开都能看完整演示。
- **真实模式**：在「设置」里填入自己的大模型 API Key（目前接了 DeepSeek，OpenAI 兼容格式），切到「真实数据」。Key 只存在浏览器 localStorage，**不进代码、不上传**。

> ⚠️ 安全提醒：**切勿把 API Key 硬编码进代码再提交**——仓库是公开的，会被抓取盗刷。Key 一律走设置里的 localStorage。

### 测试子模式

- **模型记忆**：测大模型训练记忆里的认知（裸 API 场景）。
- **联网检索**：提示词要求模型基于可查证公开信息回答并列出来源，贴近带搜索的 AI 产品；结果会被提取聚合成「实测 TOP 引用源」排行。

## GEO 逻辑链（核心方法论）

品牌要被 AI 引用，必须闯过 5 环，任何一环断了都不会被引用：

1. **内容存在**（你可控）— 有没有可被抓取的结构化内容
2. **信源覆盖**（你可控）— 有没有铺到模型爱抓的源
3. **被检索命中**（半黑盒）— 提问时有没有抓到你
4. **被采信引用**（黑盒）— 抓到 ≠ 会引用，取决于跨源共识
5. **生成呈现**（黑盒+随机）— 排第几、正负面、采样随机

`buildChain()` 用真实测试数据推断每一环状态，自动定位断点。核心思想：**越往后越黑盒，力气要花在 ①② 可控环，别在黑盒里硬赌。**

## 已知的 GEO 局限（诚实边界）

外部黑盒探测本质上有三类不准，做客户预期管理时要讲清楚：

- **测量不准**：同一问题多次采样答案不同 → 用多次采样 + 置信区间。
- **归因不准**（最难）：引用率涨了证明不了是你的功劳还是模型自己变了 → 存证时间线 + 竞品对照 + 接 AI 转介流量埋点。
- **跨时不准**：模型每几周静默更新，基线在漂 → 测相对基准（你 vs 竞品同期）抵消漂移。
